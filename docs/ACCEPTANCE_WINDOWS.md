# Windows PC 인수 확인 절차 (명세 12.4 확인 지점 2, 14.4)

클라우드에서 확인할 수 없는 항목만 남았습니다. Windows PC에서 아래 순서로 확인합니다.
PC가 세션에 연결되어 있으면 Claude가 직접 진행하고, 아니면 사용자가 진행 후 결과(CSV 파일)를 알려 주면 됩니다.

## 준비

1. GitHub Actions 최신 실행의 아티팩트 `stacklab-windows-installer`에서 `StackLab-Setup-<버전>.exe`를 받습니다.
2. 설치 → 시작 메뉴 또는 바탕화면의 StackLab 실행.
3. `설정` → `성능 측정 오버레이 표시` 켜기. 이후 측정값이 `%APPDATA%\StackLab\perf\perf-<시각>.csv`에 1초마다 쌓입니다.

## 확인 항목

| # | 항목 (14.4) | 방법 | 통과 기준 |
|---|---|---|---|
| 1 | 설치·제거 | 설치 프로그램 실행, 제거 후 재설치 | 오류 없음, 제거 후 기록 유지 |
| 2 | 60FPS 이상 | 문제 화면 3분, AI 대결 3판, 40라인 1회 동안 오버레이 확인 | CSV `fps` 평균 ≥ 60 (모니터 주사율이 60Hz면 약 60) |
| 3 | 고주사율 모니터 | 144Hz 등에서 같은 측정 | `fps`가 모니터 주사율 근처, 게임 속도(60Hz 시뮬레이션)는 동일, 끊김 없음 |
| 4 | 입력 처리 추가 지연 ≤ 16ms | 문제·40라인에서 평소처럼 조작 | CSV `input_ms_max` ≤ 16 (오버레이에서 빨간색이 뜨지 않음) |
| 5 | 입력·AI 탐색이 UI를 막지 않음 | AI 대결(L6–L7 상대 포함) 중 창 이동·조작 | `frame_ms_max`가 크게 튀지 않음, `bot_waits`가 0 근처 |
| 6 | 조작감 | DAS/ARR/SDF를 평소 TETR.IO 값으로 맞추고 비교 | 사용자 판단 |
| 7 | 한글·화면 | 모든 화면 열어 보기 | 글자 깨짐·잘림 없음 |
| 8 | 강제 종료 복구 | 문제 도중 작업 관리자로 종료 → 재실행 | 같은 문제부터 이어짐, 문제 수 그대로 |
| 9 | 백업/복원 | 통계 → 백업·복원에서 백업 후 복원 | 복원 후 기록 동일 |
| 10 | **1세트 직접 완주** | 진단(또는 건너뛰기) → 36문제 → 미니 2회 → BO3 | 끝까지 막힘 없이 진행, 결과 화면 표시 |

기준 사양(명세 12.1): Windows 10/11, 4코어 CPU, 8GB RAM, 내장 그래픽. 측정한 PC의 CPU·GPU·모니터 주사율을 같이 기록해 주세요.

## 결과 기록

측정 후 `docs/reports/step7_windows_perf.md`에 PC 사양과 CSV 요약(평균·최대)을 적고, 항목별 통과 여부를
`docs/PROGRESS.md`의 STEP 7 절에 반영합니다. 문제가 있으면 원인과 조치를 `docs/DECISIONS.md`에 기록합니다.

## 문제가 생기면

- 창이 안 뜸/화면 깨짐: 환경 변수 `STACKLAB_RENDERER=glow`로 실행해 보고 결과를 알려 주세요.
- 설치 확인: 명령 프롬프트에서 `"%LOCALAPPDATA%\Programs\StackLab\stacklab.exe" --self-check` →
  `%APPDATA%\StackLab\self-check.txt`.
